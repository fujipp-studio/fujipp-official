# แผนลูกเล่นเทศกาลบนเว็บไซต์

สถานะ: เอกสารแผนต้นฉบับสำหรับอ้างอิง พัฒนาและรวมเข้า `main` แล้วใน [PR #125](https://github.com/fujipp-studio/fujipp-official/pull/125) โดยติดตั้ง migration ในฐานข้อมูลเว็บไซต์บน VPS แล้ว ดูคู่มือระบบที่ [seasonal-effects.md](seasonal-effects.md)

## เป้าหมายและขอบเขตรุ่นแรก

- เพิ่มของตกแต่งเคลื่อนไหว โดยคงสี ฟอนต์ ขนาด และเลย์เอาต์เดิมของเว็บไซต์
- ทำงานร่วมกับ Light / Dark / System ที่มีอยู่ ไม่แก้สถานะใน `useThemeStore`
- เลือกแสดงได้ครั้งละหนึ่งเทศกาล: `NONE`, `HALLOWEEN`, `CHRISTMAS`, `VALENTINE`
- ค่าเริ่มต้นคือ `NONE` และเปิดใช้งานจริงหลัง Admin บันทึกเท่านั้น
- Admin เลือกเทศกาล ดูตัวอย่าง และเปิด–ปิดสำหรับผู้เข้าชมทั้งเว็บไซต์ได้
- ชื่อ ตัวเลือก สถานะ และข้อความแจ้งผลรองรับไทยและอังกฤษ
- รุ่นแรกควบคุมด้วยมือ การตั้งวันที่หรือธีมประจำเดือนอัตโนมัติยังอยู่นอกขอบเขต

## รูปลักษณ์และจังหวะ

จำนวนด้านล่างเป็นเพดานเริ่มต้นสำหรับปรับจากการดูตัวอย่างจริง ไม่ใช่จำนวนที่ต้องปรากฏพร้อมกันตลอดเวลา

| เทศกาล | รูปแบบ | คอม | มือถือ |
| --- | --- | --- | --- |
| Halloween | ผี SVG น่ารัก 4 แบบ เช่น โบกมือ ขี้อาย ยิ้ม และง่วง ลอยช้า ๆ พร้อมค่อย ๆ ปรากฏและจางหาย | พร้อมกันไม่เกิน 2 ตัว | ไม่เกิน 1 ตัว |
| Christmas | หิมะเม็ดเล็ก บางเบา ความเร็วและการแกว่งต่างกัน | ไม่เกิน 24 เม็ด | ไม่เกิน 10 เม็ด |
| Valentine’s | หัวใจเล็ก ลอยขึ้นและจางหายเป็นช่วง | พร้อมกันไม่เกิน 3 ดวง | ไม่เกิน 1 ดวง |

- ผีและหัวใจมีช่วงพักระหว่างการปรากฏ โดยเน้นบริเวณริมจอ
- หิมะกระจายบาง ๆ ทั่วจอ และลดความทึบเหนือบริเวณเนื้อหา
- ใช้ไฟล์ SVG ภายในโปรเจกต์ เพื่อควบคุมรูปแบบและไม่ต้องโหลดจากบริการภายนอก
- ปรับสีเฉพาะตัวของตกแต่งผ่าน Semantic tokens ให้เห็นได้ในทั้งสองโหมด โดยไม่เปลี่ยนสีเว็บไซต์
- ไม่มีเสียง การกระพริบ หรือการเปลี่ยนรูปร่าง cursor

## ประสบการณ์ใน Admin

เพิ่มเมนู “ลูกเล่นเทศกาล / Seasonal effects” ที่ `/admin/seasonal-effects`
ผ่าน Admin shell และรายการเมนูกลางเดิม เพื่อให้เข้าถึงได้ทั้งจากหน้า Dashboard และ Admin tools

1. แสดงเทศกาลที่ใช้งานจริง พร้อมเวลาที่บันทึกล่าสุด
2. เลือกจากการ์ด ปิด / Halloween / Christmas / Valentine’s
3. กด “ดูตัวอย่าง” เพื่อเปิดเอฟเฟกต์เฉพาะหน้า Preview ในเครื่องของ Admin
4. ปิด Preview หรือเปลี่ยนตัวเลือกได้ โดยยังไม่เปลี่ยนสิ่งที่ผู้เข้าชมเห็น
5. กด “บันทึก” เพื่อใช้ค่าที่เลือกกับเว็บไซต์
6. ถ้าบันทึกล้มเหลว แสดงข้อผิดพลาดและให้ลองใหม่ โดยไม่แสดงสถานะสำเร็จ

Preview ใช้ renderer เดียวกับเว็บจริง และแยก draft ออกจากค่าที่บันทึกแล้ว
เมื่อออกจากหน้า Admin ต้องล้าง Preview และคืนค่าที่บันทึกจริง
หากเปิดการลดการเคลื่อนไหว ให้แสดงคำอธิบายและภาพนิ่งของตัวอย่างแทนแอนิเมชัน

## โครงสร้างที่เข้ากับโค้ดปัจจุบัน

### Frontend

- เพิ่ม feature `frontend/src/features/seasonal-effects/` สำหรับ API, renderer, assets และตัวเลือกเทศกาล
- เพิ่ม Pinia store สำหรับค่าที่อ่านจากเซิร์ฟเวอร์ ใช้ร่วมกันระหว่าง `App.vue` และหน้า Admin
- ติดตั้ง renderer เพียงชุดเดียวที่ `frontend/src/App.vue` และโหลดส่วนแสดงผลเมื่อมีเอฟเฟกต์ที่ต้องใช้
- เพิ่มหน้า Admin และเมนูใน `useAdminNavigation.ts` รวมถึง route metadata และคำแปลที่เกี่ยวข้อง
- ใช้ `apiFetch` และ `adminRequest` เดิมสำหรับการเรียก API
- โหลดการตั้งค่าเบื้องหลัง การแสดงเนื้อหาหน้าเว็บไม่ต้องรอเอฟเฟกต์
- อ่านค่าเมื่อเปิดเว็บ และตรวจการเปลี่ยนแปลงทุก 60 วินาทีเฉพาะขณะแท็บมองเห็นอยู่
- เมื่อกลับเข้าแท็บ ตรวจใหม่หากข้อมูลเก่ากว่า 60 วินาที และไม่ให้มีคำขอซ้อนกัน
- หลัง Admin บันทึกสำเร็จ อัปเดต store ในหน้าปัจจุบันทันที ส่วนผู้เข้าชมที่เปิดเว็บค้างจะรับค่ารอบถัดไป
- โหลดค่าครั้งแรกไม่ได้หรือได้รับค่าเทศกาลที่ไม่รู้จัก ให้แสดงเว็บไซต์ตามปกติโดยปิดเอฟเฟกต์
- หากตรวจค่าใหม่ล้มเหลวหลังเคยโหลดสำเร็จ ให้เก็บค่าล่าสุด และรอตรวจรอบถัดไป

### Backend และข้อมูลถาวร

ใช้แนวทางการตั้งค่ากลางแบบหนึ่งแถวคล้าย Donation settings ที่มีอยู่ แต่แยกข้อมูลของเทศกาลออกมา

- ตารางเสนอ: `private.website_effect_settings`
- คอลัมน์: `id` บังคับเป็น 1, `effect` พร้อมข้อจำกัดค่าที่อนุญาต, `updated_at`, `updated_by`
- สร้างแถวเริ่มต้นเป็น `NONE` ผ่าน migration ใน `supabase/migrations/`
- เปิด RLS และให้สิทธิ์เฉพาะ backend role ที่จำเป็น ไม่ให้ browser เขียนตารางโดยตรง
- `GET /api/v1/site/seasonal-effects` — ผู้เข้าชมอ่าน `effect` และ `updatedAt` ได้โดยไม่ต้องเข้าสู่ระบบ
- `GET /api/v1/admin/site/seasonal-effects` — Admin อ่านค่าจัดการ
- `PUT /api/v1/admin/site/seasonal-effects` — Admin บันทึก `effect` ที่ผ่าน validation
- ตรวจบทบาท `ADMIN` ที่ backend ตาม pattern เดิม และเพิ่มเฉพาะ public GET ใน `SecurityConfig`
- Public response ไม่เปิดเผยผู้แก้ไข ส่วน `updated_by` ใช้ตัวตนจาก JWT ที่ตรวจสอบแล้ว
- ใช้การตั้งค่า cache แบบ revalidate เพื่อให้การปิดเอฟเฟกต์มีผลตามรอบตรวจ ไม่ค้างจาก cache เก่า

## การแสดงผลและประสิทธิภาพ

- ชั้นตกแต่งใช้ `pointer-events: none` และ `aria-hidden="true"` ไม่รับ focus และไม่สร้าง scrollbar
- แสดงตามหน้าปกติของเว็บ แต่ซ่อนจากหน้า Admin และหน้ารับผลเข้าสู่ระบบ ยกเว้น Preview ที่ Admin เปิดเอง
- ซ่อนชั่วคราวเมื่อเปิดกล่องโต้ตอบ ดูรูปเต็ม หรือเมนูแบบ overlay เพื่อให้เนื้อหาส่วนนั้นชัดเจน
- ใช้ระดับชั้นตาม z-index tokens เดิม และไม่วางของตกแต่งเหนือ Navbar หรือกล่องโต้ตอบ
- ใช้ CSS transform และ opacity เป็นหลัก สุ่มเส้นทางตอนเริ่มรอบ ไม่อัปเดต Vue state ทุกเฟรม
- หยุดแอนิเมชันเมื่อแท็บถูกซ่อน และล้าง timer / listener / animation เมื่อปิดเอฟเฟกต์หรือออกจากหน้า
- เมื่อ `prefers-reduced-motion: reduce` ทำงาน ให้ปิดแอนิเมชันอัตโนมัติ รวมถึงเมื่อผู้ใช้เปลี่ยนค่าระหว่างเปิดเว็บ
- เมื่อเลือก `NONE` ต้องไม่มีอนุภาคหรือ animation loop ทำงาน

## ลำดับพัฒนา

1. ทำ renderer และ SVG ทั้งสามเทศกาล พร้อมหน้าตัวอย่างภายในสำหรับปรับจำนวน ขนาด ความทึบ และจังหวะ
2. เพิ่ม migration และ API พร้อมทดสอบการอ่านสาธารณะ การจำกัดสิทธิ์ และ validation
3. เพิ่มหน้า Admin การดูตัวอย่างเฉพาะเครื่อง การบันทึก และข้อความไทย–อังกฤษ
4. เชื่อมค่าจริงกับ `App.vue` พร้อมการอัปเดตค่า การซ่อนตอนเปิด overlay และการจัดการ reduced motion
5. ตรวจภาพและการใช้งาน Desktop / Mobile และ Light / Dark แล้วปรับจังหวะก่อนส่งงาน

ก่อนเริ่ม implementation ให้ใช้ task branch จาก `main` ตามกฎของ repository
และเก็บการแก้ UI จากงานก่อนหน้าให้แยกจากงานเทศกาล ไม่ปะปนใน commit เดียวกัน

## เกณฑ์ตรวจรับ

- สี ขนาดตัวอักษร และเลย์เอาต์เดิมไม่เปลี่ยนเมื่อสลับเทศกาล
- เอฟเฟกต์ทั้งสามตรงกับตัวอย่างและไม่ขวางการคลิก การพิมพ์ หรือการเลื่อนหน้า
- เปลี่ยน route แล้วไม่มี renderer ซ้ำหรือจำนวนอนุภาคสะสม
- Preview ไม่บันทึกหรือเปลี่ยนเอฟเฟกต์ของผู้เข้าชมคนอื่น
- บันทึกแล้วรีเฟรชยังคงค่าที่เลือก ผู้เข้าชมที่ไม่ได้เข้าสู่ระบบอ่านค่าได้
- ผู้ใช้ทั่วไปแก้ค่าไม่ได้ และค่าเทศกาลที่ไม่อนุญาตถูกปฏิเสธ
- ปิดเอฟเฟกต์แล้วของตกแต่งและงานแอนิเมชันถูกนำออกครบ
- ปรับตามหน้าจอ แท็บที่ซ่อน การลดการเคลื่อนไหว และสถานะกล่องโต้ตอบได้ถูกต้อง
- ทดสอบ API failure และการลองบันทึกใหม่ ไม่ทำให้หน้าหลักใช้งานไม่ได้
- ก่อน commit/push รัน frontend build, unit tests, lint และ visual QA ตามกฎเดิม รวมถึง backend checks ที่เกี่ยวข้อง

## การนำขึ้นใช้งาน

ปล่อย migration ก่อน backend และ frontend โดยคงค่าเริ่มต้นเป็น `NONE`
ตรวจ Preview และการบันทึกหลังติดตั้งครบ แล้วจึงให้ Admin เลือกเทศกาลที่ต้องการเปิดจริง
การเปิดเดือนอัตโนมัติ การกำหนดความหนาแน่นเอง การอัปโหลดรูป และเอฟเฟกต์ตาม cursor ยังไม่รวมในรุ่นแรก
